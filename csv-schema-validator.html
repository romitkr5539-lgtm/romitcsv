Check your CSV against an expected schema
Many import tools expect column headings to be present in a specific order. A file with the right data but a renamed, missing, or extra column can fail validation or map values into the wrong fields. The Schema Validator compares the CSV’s first row with a list of headings you provide and reports where they differ.

    
What the schema comparison checks
  • Missing columns: expected headings that do not appear in the CSV.
  • Unexpected columns: actual headings that are not listed in your expected schema.
  • Name or order mismatches: each expected heading is compared with the actual heading at the same position.

    
Enter one expected name per line in the required order. Blank lines are ignored, and surrounding whitespace in the expected and actual heading names is trimmed before comparison. Matching is case-sensitive, so email and Email are different. The first CSV row is treated as headers; this tool does not validate the data values in the rows below them.

    
How to validate a CSV schema
  1. Choose or drop a CSV, TSV, or plain-text file up to 50 MB, or paste delimited data.
  2. Review the source table and confirm that the first row contains the actual headings.
  3. Enter the required headings, one per line and in the expected order.
  4. Select Validate schema, then review or download the comparison report.

    
The validator identifies differences but does not rename or reorder columns. Files are processed in your browser and are not sent to the RomitCSV server. For blank or repeated headings, use the CSV Header Checker; for row-width and quote checks, use the CSV Validator.

    
Frequently asked questions
How should I enter the expected schema?
Enter one column heading on each line, in the exact order required by the system that will receive the CSV. Empty lines are ignored.
Does the comparison ignore capitalization?
No. It trims whitespace at the beginning and end of heading names, but matching is case-sensitive.
Why can one missing column create more than one finding?
The report can show that an expected name is missing and that its position does not match the actual header. These describe separate schema differences.
Does this check the values in every row?
No. It compares column headings and their order. It does not validate cell types, required values, or row lengths.
Will it fix or reorder my CSV?
No. The tool creates a report and leaves the source unchanged so you can decide how to resolve the differences.
Can I paste CSV data?
Yes. Paste comma-, tab-, semicolon-, or pipe-delimited text, load it, then enter the expected headings in the workspace.
