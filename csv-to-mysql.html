CSV TO MYSQL GUIDE
    
Generate MySQL INSERT statements from CSV
When you need to load rows from a spreadsheet export into MySQL, INSERT statements provide a direct way to add the data to an existing table. This converter reads the first row as column names and creates INSERT statements for the remaining rows. Set a target table, inspect the parsed values, and save the SQL for review.

    
How the generated MySQL SQL is formatted
Table and column identifiers use MySQL backticks, including escaping embedded backticks. Apostrophes in text values are escaped, and backslashes are handled for MySQL string literals. The tool emits values as text rather than guessing whether a cell is a number, date, or another type. MySQL applies the destination column rules when the statements run.
Records are grouped into INSERT batches of up to 500 rows. Empty cells become empty string values by default. Select Write empty cells as NULL to generate SQL NULL for them. Empty strings and NULL represent different data, so match this setting to your schema and source data.

    
Set the MySQL table name
The default destination is csv_data. You can enter a schema-qualified name such as app.customers; the schema and table identifiers are quoted separately. The first CSV row becomes the column list. Blank or repeated headings are made unique, short rows are padded with empty values, and extra cells are retained under generated column names.

    
Convert CSV to MySQL INSERT statements
  1. Drop a CSV, TSV, or text file into the uploader, browse for a file, or paste delimited data.
  2. Check the source table and set the destination table name.
  3. Choose whether blank cells should become empty strings or SQL NULL.
  4. Generate the INSERT statements, review the SQL, then copy or download the .sql file.
The conversion runs locally in your browser. This page does not connect to a MySQL server, create a table, inspect your database schema, or execute SQL. Review the statements and test them against a safe database first. MySQL behavior can depend on server settings such as SQL mode, so confirm the output matches your environment.

    
Frequently asked questions
Does this create a MySQL table?
No. It creates INSERT statements for a table that already exists. Create the table separately with compatible columns and data types.
Does it infer numeric and date types?
No. Cell contents are emitted as quoted text values. MySQL may coerce them to the target column type when inserted, if the values are valid for that type.
How are blank cells handled?
By default, blank cells are written as empty strings. Enable the NULL option to write SQL NULL. The two values behave differently, especially with nullable columns and queries.
Are quotes and backslashes in values handled?
Apostrophes are doubled and backslashes are escaped for MySQL string literals. Check your server's SQL mode when using the generated statements.
Can I specify a database or schema name?
Yes. Use a qualified name such as app.orders. Each identifier part is quoted with MySQL backticks.
Does the page upload my CSV or run the SQL?
No. The browser reads the file locally. It does not send the data to a server or execute the generated SQL.
