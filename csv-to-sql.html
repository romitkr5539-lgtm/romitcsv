CSV TO SQL GUIDE

Prepare a CSV import for a relational database

When a database table starts as a spreadsheet export, the repetitive work is translating column names, choosing field types, and writing one INSERT row for every record. This converter builds a CREATE TABLE statement and INSERT statements from the CSV so you can review a starting point before using it in your database workflow.

Choose SQLite, PostgreSQL, or MySQL to generate syntax for that dialect. The tool infers a type from the non-empty values in each column: whole numbers, decimal values, booleans, or text. It shows the inferred types alongside the data preview so you can catch a column that needs a different type before copying the SQL.

Check how headings and empty cells are handled

With First row contains column names selected, the first row becomes the table headings and the remaining rows become records. Turn it off when the file has no header; generated names such as column_1 will be used and the first row will be inserted as data. Blank or repeated headings are replaced with safe, unique names.

By default, empty cells become SQL NULL. Turn that option off to write empty text values instead. Apostrophes inside text are doubled, and table and column names are quoted using the selected database dialect. If you enable Drop table before creating it, the output adds DROP TABLE IF EXISTS before the table definition.

Review the generated statements before running them

SQL output is a starting script, not a database connection. Check the inferred types, table name, and values against your actual schema. In particular, confirm that identifiers, dates, decimal precision, and required fields match your database expectations. The converter keeps values as text unless a whole column consistently looks numeric or boolean.

Questions about converting CSV to SQL

Which database formats are supported?

The generator supports SQLite, PostgreSQL, and MySQL syntax for table and column identifiers and common data types.

How are column types inferred?

Types are inferred from non-empty data cells. Consistent integers, decimal numbers, and true/false values receive matching types; other or mixed values become text.

Does an empty CSV cell become NULL?

Yes, by default. Turn off Treat empty cells as NULL to generate empty text values instead.

Does the converter execute SQL?

No. It generates a SQL file for you to inspect and run in your own database tools.

Is my CSV uploaded?

No. The file is parsed and converted in your browser.
