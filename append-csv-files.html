Append CSV Files by Stacking Their Rows

Appending is a straightforward way to combine exports that use one consistent table layout. It places the data rows from each file below the previous file’s rows and keeps the first file’s column headings once at the top. Use it for recurring reports, weekly extracts, or batches of records with the same fields.

For example, if two monthly files each contain Date,Order ID,Amount, appending them creates one table with the same three columns and all records stacked together. The second file’s heading row is not copied as a data record.

Inputs must have the same headings and order

Every selected file must have exactly the same heading text in the same sequence. Capitalization, spacing, and column order all matter. Customer ID is different from customer id, and Name,Email is not the same layout as Email,Name. If a file fails this check, the appender reports which source does not match so you can correct or replace it.

Appending does not try to align columns or guess which differently named fields are equivalent. If your files use different column positions or have additional headings, use the multiple CSV merger, which matches fields by heading.

Choose the source order and append

  1. Select or drop at least two CSV, TSV, or supported delimited TXT files, up to 50 MB each.
  2. Review their order. Records are appended in the order shown.
  3. Add another file or remove a source before processing if needed.
  4. Select Append CSV Files. If the headings match, preview the stacked table and download the new CSV.

The result preview is paginated, while the download includes all appended records. Values containing commas, line breaks, or quotation marks remain within their fields. TSV and supported delimited text files are converted to comma-separated CSV output.

What appending does not change

Rows are not sorted, filtered, or deduplicated. Duplicate records remain, and each source contributes its data rows in its listed order. The output contains one heading row from the first source and then the records from every file. The original files are left unchanged.

Files are read and processed in your browser. Their contents are not sent to the RomitCSV server. For a key-based match between two datasets, use the CSV Joiner instead of appending.

APPEND CSV FAQ

Questions About Appending CSV Files

How is appending different from merging?

Appending stacks rows and requires identical headings in the same order. Merging aligns fields by heading and can accommodate different column orders or additional columns.

Are headings repeated between files?

No. The output keeps the first file’s header once. The later header rows are not added as data.

What if two files have different column orders?

The appender stops and identifies the mismatch. Reorder the columns or use the multiple-file merger to match by heading.

Does appending remove duplicates?

No. Duplicate rows are preserved exactly as records in the source files.

Does file order affect the result?

Yes. The source list order determines which file’s records appear first.

Can I append TSV files?

Yes. CSV, TSV, and supported delimited TXT files can be appended if their headings match exactly.

Can I add or remove files before appending?

Yes. Add more sources or remove listed files before running the append.

Are my files uploaded?

No. They are processed in your browser, and the originals are not modified.

Check the combined row count before exporting

Before importing the appended file into a database or spreadsheet, review the heading row and source order. Compare the result row count with the totals in the source files, and remember that repeated records remain unless you remove them in a separate cleanup step.
