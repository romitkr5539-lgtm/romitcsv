Catch CSV Problems Before an Import

A file can look fine in a spreadsheet and still fail when another system imports it. A row may have one field too few, a header may be repeated, or a quoted value may never close. The Validator points out these structural problems and several common data issues, then highlights affected rows in a preview.

Read the Findings

Upload or paste the file, review the full source table, then look at the error and warning counts. Filter findings to show all items, errors, or warnings. Rows with findings are highlighted, and each finding gives the row number to inspect.

FindingExample or meaning
Different number of fieldsIf the header has id,name,email but a row is 7,Ada, that row has two fields where three are expected. The validator marks it as an error.
Empty or repeated headerBlank column names are errors. Repeated names are also errors; Name and name count as duplicates.
Blank rowA row containing only empty or whitespace values is reported as a warning. Remove it only if it is not meaningful in your file.
Repeated data rowA full row that matches an earlier row after trimming surrounding whitespace is a warning. Matching is case-sensitive, and no rows are deleted.
Whitespace or empty cellsLeading or trailing whitespace is a warning. The report counts blank cells and fields missing from short rows.
Quote problemAn unclosed quoted value or a quote inside an unquoted field is reported as an error. A quote inside a quoted value can be escaped by doubling it: "".

An error means the validator found a structural or parsing problem. A warning flags something that may be intentional, such as an empty row or a repeated record, so review the row before changing it.

What This Check Does Not Decide

The first record is always treated as the header. The tool does not know which fields your application requires, whether an email address is valid, or whether a date or number follows your own rules. It checks general CSV structure and common patterns; use the schema or import rules for the system that will receive the file.

The separator is guessed from the first non-empty line by looking for commas, semicolons, tabs, or pipes. If a quoted heading itself contains one of those characters, check the preview because that guess may be wrong.

Fix and Recheck

The Validator reports issues but does not change the source file. For whitespace, blank rows, or duplicate rows, try the CSV Cleaner. To correct a particular heading or cell, use the CSV Editor, then upload or paste the revised copy here to check it again.

File Handling

CSV and TSV files up to 50 MB are read in your browser; the Validator does not send them to the RomitCSV server. Larger files are not accepted. Results and performance depend on your browser and device.

Common Questions

Does the Validator remove duplicate rows?

No. It marks later complete-row matches as warnings. Use the Cleaner if you want to remove duplicates.

Why does my file show a different field count?

That row has more or fewer separators than the header, or the separator may have been guessed incorrectly. Check the indicated row and the data preview, especially if the first line contains quoted separators.

Does a warning mean the CSV is invalid?

Not necessarily. A repeated row, blank row, or surrounding whitespace may be intentional. Review the finding in context before deciding what to change.
