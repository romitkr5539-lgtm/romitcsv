Find out how a CSV file is encoded
CSV stores rows and fields as text, but the bytes behind that text can use different character encodings. If the program opening a file assumes the wrong encoding, names and other non-English characters may appear as question marks or unreadable symbols. This detector examines the original file bytes for common markers and checks whether the data is valid UTF-8, then shows the decoded CSV as a table.

    
What the report tells you
  • Detected encoding: identifies UTF-8 and UTF-16 when a byte order mark is present, checks whether unmarked bytes form valid UTF-8, and flags likely UTF-16 patterns or possible legacy-encoded bytes.
  • Byte order mark: reports whether the file begins with a UTF-8, UTF-16 little-endian, or UTF-16 big-endian marker.
  • UTF-8 validation: shows whether the original bytes are valid UTF-8. UTF-16 data is expected to fail this check because it uses a different encoding.
  • File size: reports original bytes, not the number of characters shown in the preview.

    
Detection has limits. UTF-8 without a BOM can be identified when its byte sequence is valid, but many legacy encodings can represent the same byte values. “Possible legacy encoding” is a clue, not a definitive identification. Check the preview for replacement symbols or garbled text.

    
How to check a CSV file
  1. Choose or drop a CSV, TSV, or plain-text file up to 50 MB.
  2. Review the encoding summary and parsed table preview.
  3. Copy or download the report if you need to share the detection results.
  4. If the text looks wrong in another application, try importing the file with the detected encoding selected.

    
You can paste delimited text to inspect its table structure. A browser converts pasted text to a UTF-8 representation, so paste cannot reveal the original encoding or BOM. Upload the original file for that check. Files are analyzed in your browser and are not sent to our server. This tool reports encoding clues; it does not convert or rewrite the source file.

    
Frequently asked questions
What is a byte order mark in a CSV file?
A byte order mark, or BOM, is a short byte sequence at the start of some text files. It can identify UTF-8 or the byte order used by UTF-16, and some spreadsheet programs use it as a hint when opening a file.
Can the detector identify every legacy encoding?
No. Without a clear marker, different encodings can use overlapping byte values. The tool can validate UTF-8 and point out patterns that may indicate another encoding, but it cannot reliably name every legacy code page.
Why does pasted text show UTF-8?
When you paste, the browser receives characters rather than original file bytes. It encodes those characters as UTF-8 for analysis. Upload the original CSV to inspect its actual encoding and byte order mark.
Does this tool change the file encoding?
No. It reads the file and produces a report. To convert a file, use an editor or import/export option that lets you choose the target encoding.
Is my file uploaded to a server?
No. The selected file is read and analyzed in your browser. It is not sent to the RomitCSV server.
